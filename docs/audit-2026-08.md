## 1. セキュリティ

### 1.1 mobilecli を `--cors` 付きで起動している **[高]**

`src/utils/MobileCliServer.ts:222`, `:230`

```ts
'server', 'start', '--cors', '--listen', `localhost:${this.serverPort}`,
```

mobilecli の RPC サーバは `127.0.0.1:12000` 付近で待ち受ける。`--cors` を付けると
**ブラウザで開いている任意のページ**がこの RPC を叩けて、しかも**応答を読める**。
`Content-Type: application/json` の POST はプリフライトを起こすので、CORS が
無ければブラウザ側で止まる。付けた瞬間に「盲目的な CSRF」が
「読み書き両方できる API」へ格上げされる。

その API でできること:

| RPC | 攻撃者が得るもの |
| --- | --- |
| `devices.list` / `device.info` | 端末の列挙 |
| `device.screenshot` | **画面の中身**（開発中アプリ、認証画面、トークン） |
| `device.io.tap` / `.gesture` / `.text` | 端末の**操作** |
| `device.screenrecord` | `output` に**ホスト側の任意パス**を書ける（任意ファイル書き込み） |
| `device.url` | 端末で任意 URL / ディープリンクを開く |

**この拡張は CORS を必要としない。**

- 拡張ホスト側は Node の `fetch`（undici）で叩く。オリジンを持たないので CORS の
  対象外。
- webview 側は `<img src>` しか使わない。画像読み込みは CORS で制限されない
  ——`src/capture/MjpegProxy.ts:13` に自分でそう書いてある。

→ **両方の引数リストから `--cors` を落とす。** 直結ストリーム（`directStream`）が
リモート開発を含めて従来どおり映ることだけ確認すればよい。
ついでに `--listen localhost:PORT` が `0.0.0.0` / `::` へ広がらないことも
`lsof -nP -iTCP -sTCP:LISTEN` で確認しておきたい（loopback 限定なら現状で正しい）。

### 1.2 キー入力の内容が既定でログに残る **[高]**

`src/webview/SimulatorWebviewProvider.ts:407-410`

```ts
case 'keypress':
  Logger.info(`Key pressed: ${message.key}${message.special ? ' (special)' : ''}`);
```

`info` は既定のログレベルなので、**端末へ打った文字が 1 文字 1 行で
出力チャンネルへ残る。**開発中アプリのログイン画面に打ったパスワードも同じ経路で残る。
VS Code は OutputChannel の全文をメモリに保持し、古い行を捨てる API が無い
（`docs/project-review.md` §3.5.7）ので、**セッション中は消えない**し、
不具合報告でログを貼れば外へ出る。

`src/input/SimulatorInputController.ts:235`, `:253` も同じ
（送れなかったキーを `warn` の本文に載せている）。

同時に CLAUDE.md の「**高頻度パスでログを出さない**」に正面から違反している。
`touch*` を除外しているのに `keypress` が漏れている。

→ 内容ではなく**種別だけ**を、しかも `debug` で出す:

```ts
Logger.debug(`keypress (${message.special ? 'special' : 'char'})`);
```

特殊キー名（`return` / `escape` など）は内容ではないので残してよいが、
`e.key.length === 1` の文字は決して載せない。

### 1.3 RPC のエラー文へ params が丸ごと入る **[中〜高]**

`src/utils/JsonRpcClient.ts:51-55`

```ts
throw new Error(`${error.message} (method: ${method}, params: ${JSON.stringify(params)})`);
```

`device.io.text` の params は `{text: "<貼り付けた内容>", deviceId}` である。
RPC が失敗すると、**クリップボードの中身がそのまま例外メッセージに入る。**
その文字列は

1. `Logger.error('Failed to handle message', error)`（`SimulatorWebviewProvider.ts:438`）
2. `this.sendError((error as Error).message)` → webview のオーバーレイに**画面表示**

の 2 経路へ流れる。パスワードマネージャからパスワードを貼った直後に WDA が
落ちていれば、それが画面に出てログにも残る。

→ 診断に要るのは `deviceId` とメソッド名だけ。params は許可リストで絞るか、
`text` / `value` を `[redacted:<length>]` に置き換える。
`JsonRpcClient` に単体テストが無い層なので、直すついでに 1 本足したい。

### 1.4 稼働中サーバを無認証で再利用する **[中]**

`src/utils/MobileCliServer.ts:187-203`

12000〜12100 の 101 ポートへ `/health` を投げ、200 が返ったポートへ
`devices.list` を POST し、通ったものを**そのまま採用する**。

- 同じマシンの任意のローカルプロセスが 12000 を先に押さえて `/health` と
  `devices.list` に応答すれば、この拡張の**送信先を乗っ取れる**。
  以後 `device.io.text`（打鍵・貼り付け内容）と録画の保存先パスがそこへ届く。
- 走査そのものも、mobilecli とは無関係のローカルサービスへ JSON を POST しうる。

ローカル権限が要るので単独では致命的でないが、1.1 と組み合わせると
「ブラウザのタブ → ローカル RPC」の経路が生きるため、実質的な攻撃面は広い。

→ 最低限、**自分で起動したサーバだけを使う**（再利用は既定 OFF の設定にする）。
残すなら `/health` の本体が mobilecli の形をしていることを確認してから
`/rpc` を叩く。走査範囲も 101 は広すぎる（10 程度で足りる）。

### 1.5 npx フォールバックが実行時にコードを取ってきて実行する **[中]**

`src/utils/MobileCliServer.ts:70`, `:213-225`

同梱バイナリが見つからないと `npx -y @mobilenext/mobilecli@<version>` を spawn する。
版を固定しているのは良い（`npxPackageSpec()` が `package.json` から取る）が、
`-y` で確認を省き、整合性検証は無い。VSIX には darwin 版しか入らないので、
**macOS 以外では常にこの経路**になる。

→ 挙動として README に明記し、できれば初回に一度だけ確認を出す。
少なくとも `Logger.warn` で「ネットワークから取得して実行する」ことを見えるようにする。

### 1.6 `WdaSettings` が lsof の出力からポートを当てる **[低〜中]**

`src/capture/WdaSettings.ts:57-89`。`docs/project-review.md` §2.2 で既知。
`/WebDriver/i` に一致するプロセスの LISTEN ポートへ設定を POST するので、
無関係な WDA を掴む余地がある。実害は「他人の WDA の画質が変わる」程度。
mobilecli からポートを取れるならそちらが正しい。

### 1.7 webview のフッターを `innerHTML` で組んでいる **[低]**

`media/webview/main.js:735`

```js
const chip = (label, value) => `<span class="chip"><b>${label}</b> ${value}</span>`;
statsEl.innerHTML = rate + chip(t('host'), message.rssMb + 'MB') + ...;
```

値は拡張ホストが作った数値だが、**ラベルは l10n バンドル由来**なので、
翻訳に HTML が混ざれば注入される。CSP が `script-src 'nonce-…'` なので
インラインハンドラも `eval` も動かず、実害は「見た目が壊れる」に留まる。
それでも `createElement` + `textContent` で組むほうが素直で、
`t()` の戻り値を信用する前提を減らせる。

### 1.8 CSP の `img-src` が localhost 40 ポートを常時許可 **[低]**

`src/webview/SimulatorWebviewProvider.ts:1365-1377`。`directStream` が OFF でも
12200〜12219 と 12220〜12239 を許可している（HTML 生成時にポートが未定のため）。
トークンが無ければ絵は取れないので実害は薄いが、範囲は狭められる余地がある。

### 1.9 `simulator.openUrl` にスキーム検証が無い **[低]**

`src/extension.ts:41-53`。空文字以外は何でも `device.url` へ渡る。
入力するのはユーザー本人なので実害は無いが、明らかに URL でない入力は弾きたい。

### 1.10 良かった点（意図的に守られている）

- **ループバック限定＋起動毎トークン。** `MjpegProxy`（`randomBytes(24)` /
  `timingSafeEqual`）と native の `startServe`（`INADDR_LOOPBACK` 固定 /
  早期 return しない `tokenEquals`）の両方で、経路とトークンが揃わないものを
  404 で落として存在自体を伏せている。タイミング攻撃まで見ているのは丁寧。
- **バイナリのパスが設定可能でない。** `mobilecli` も `simhid-server` も
  `extensionUri` 由来で、`adb` は環境変数と既定位置からしか探さない。
  つまり**悪意あるリポジトリの `.vscode/settings.json` を踏んでもコード実行に化けない。**
  拡張ではよく見落とされる性質で、ここは明確に正しい。
- **CSP に `unsafe-eval` が無く、`script-src` は nonce のみ。** 埋め込む l10n JSON も
  `<` を `\u003c` へ逃がしている（`SimulatorWebviewProvider.ts:1395`）。
- **`adb` を直に叩くのは `AdbTouch` の中だけ**で、渡すのは `Math.round` 済みの
  整数座標だけ。`adb shell` へ流す行に文字列が混じらないのでコマンド注入面が無い。
- 秘密情報・テレメトリ・ループバック外への通信がいずれも無い。
- CI に `npm audit` と TruffleHog がある。

**`npm audit`**: high 1 件（`picomatch` ≤2.3.1、`@vscode/vsce` 経由の
**devDependency**）。VSIX には入らないので利用者への影響は無いが、
`continue-on-error: true` の監査ジョブを意味あるものに保つため
`npm audit fix` は当てておきたい。

## 2. ストレージ管理 — **9.5 / 10**

CLAUDE.md の「永続ストレージを使わない」が**実装と一致している**ことを確認した。

- `globalState` / `workspaceState` / `secrets` / `storageUri` の参照が 1 件も無い。
- 拡張が自分でファイルを書くのは、**ユーザーが保存ダイアログで選んだ 1 ファイル**だけ
  （`vscode.workspace.fs.writeFile`、`SimulatorWebviewProvider.ts:1233`）。
- 録画は mobilecli が保存先パスへ直接書くので、拡張は一時ファイルを持たない。
- `MjpegProxy` / `SidecarCapture` の直結配信もメモリ上のフレームだけを扱う。
- `dirSizeBytes` はシンボリックリンクを辿らず、`.git` と開発用 `node_modules` を
  除外しているので、F5 起動時に数十秒かかる罠も避けている。

**1 点だけ補足したい**: `ResourceStats.storageMb` が測るのは拡張ディレクトリだけで、
**実際に増えるもの（mobilecli が入れる WebDriverAgent の DerivedData、
npx 経路の npm キャッシュ）は範囲外**。コメントには書いてあるが、フッターの
「Extension」というラベルだけを見ると「この拡張のディスク使用量」と読める。
数値の意味が誤解されない語（"Bundle" 等）にするか、WDA のパスも足すと、
「測れる状態を保つ」という方針がより実態に近づく。

## 3. メモリ・リソース管理 — **8.5 / 10**

### 3.1 守られていること（確認済み）

上限と破棄条件がセットで書かれている箇所を全て突き合わせた。**漏れは無い。**

| 入れ物 | 上限 | 破棄 |
| --- | --- | --- |
| `MjpegParser` のバッファ | 10MB / パート 10MB | 例外 → `reset()` → 張り直し |
| `SimhidSidecar.stdoutBuf` | 1MB（改行なし） | 超過で丸ごと破棄 |
| `SimhidSidecar.pending` | — | `onExit` / `dispose` で必ず `clear()` |
| `WdaBackend.points` | 240 点 | 超過で間引き（始点・終点・時刻は保つ） |
| `AdbTouch.buf` / `.pending` | 4096B / 8 件 | 超過で切り詰め・滞留で `kill()` |
| webview の `pointers` | 10 件 | 古い pointerId から落とす |
| webview の `trailPoints` | 40 点 | `shift()` |
| 録画 | 10 分 | タイマー・切断・非表示・`dispose` |
| 再接続 | 指数バックオフ 10 秒上限 | ログは最初の 3 回だけ |

さらに、

- **「捨てる判断」まで書かれている。** `sendNoWait` は stdin が詰まっている間
  `touchMove` を捨てる（最新座標だけが意味を持つので軌跡が歪まない）。
  `AndroidBackend` も「最新の 1 点だけ」を送る。これは正しい設計判断。
- **子プロセスは全て SIGTERM → 猶予 → SIGKILL**（`MobileCliServer:276-284`、
  `SimhidSidecar:302-310`）。孤児が残らない。
- **全てのタイマーに `unref()`** が付いていて、拡張ホストの終了を遅らせない。
- **非表示 2 分でサイドカーを解放**（`armInputRelease`）。使い回しと解放の両立。
- `resolveWebviewView` の冒頭で前回のリスナーを外し、`onDidDispose` で
  破棄済み `WebviewView` の参照を落としている（差し替え時に新しい方を消さない
  ガードまである）。
- `test/memory-leak.test.js` が上限・タイマー解放・参照破棄を**回帰として**見ている。

**この規律の水準は、同種の VS Code 拡張の中では明確に上位。** 減点は次の 4 点だけ。

### 3.2 出力チャンネルが唯一の無制限の入れ物で、そこへ打鍵を書いている **[中]**

1.2 の裏面。VS Code は OutputChannel の全文をメモリに持ち、拡張から古い行を
捨てる API は `clear()` しか無い（既知・§3.5.7）。**そこへ 1 キーストローク 1 行を
既定レベルで書いている**ので、この拡張が持つ唯一の「増える一方の入れ物」に
最も高頻度の入力を流していることになる。

概算: 100 字/分で 4 時間なら約 24,000 行・2MB 前後。`Clear Logs` を押すまで減らない。

→ 1.2 の修正でそのまま解消する。**セキュリティとメモリの両方が同じ 1 行で直る。**

### 3.3 `MjpegProxy` を directStream を切ったあとも畳まない **[低]**

`SimulatorWebviewProvider.dispose()` でしか `mjpegProxy.dispose()` を呼んでいない。
`directStream` を OFF に戻しても、サイドカー経路へ切り替わっても、切断しても、
**HTTP リスナーとトークンはセッションが終わるまで生き続ける。**
「確保したものは必ず捨てる」に照らすと畳むべき。
`onConfigurationChanged` で `!isDirectStreamEnabled()` なら破棄、
`disconnect()` でも破棄するのが素直。

### 3.4 `ensureProxy()` が `portMapping` を配列ごと置き換える **[低]**

`SimulatorWebviewProvider.ts:475-478` は `portMapping: [{...}]` と**上書き**し、
`allowStreamPort`（:456-464）は**追記**する。サイドカーの配信ポートを登録したあとに
`ensureProxy()` が走ると、その許可が消える。今は 2 経路が排他なので表面化しないが、
片方が追記・片方が上書きなのは事故の種。`allowStreamPort` に寄せたい。

### 3.5 切断済みクライアントの上流セッションを閉じずに抜ける **[低]**

`src/capture/MjpegProxy.ts:104-106`

```ts
const sessionUrl = await this.openSession(deviceId);
if (res.writableEnded || res.destroyed) return;   // ← mobilecli 側のセッションは開いたまま
```

コメントどおり「中継しない」だけで、**開いたセッションを閉じていない**。
mobilecli 側にセッションが積み残る。接続と切断を繰り返すと溜まる可能性がある。

### 3.6 `activate()` が同期の子プロセス起動でブロックする **[低・起動性能]**

`MobileCliServer` の constructor が `execFileSync(binaryPath, ['--version'])` を呼ぶ
（`:57`）。この constructor は `SimulatorWebviewProvider` 経由で `activate()` から
呼ばれるので、**拡張ホストのスレッドが `--version` の実行中ずっと止まる。**
macOS で隔離属性の付いた未署名バイナリの初回実行は Gatekeeper 検証で
体感できる時間かかることがある。

→ 存在確認（`fs.existsSync`）だけを constructor に残し、実行可否の確認は
`launchServer()` の中で非同期に行う。
